# 報價系統 手機／平板 PWA 盤點（2026-10-07，只讀盤點，未改任何程式）

對象：repo 根目錄 `index.html`（「宇德室內裝修 - 快速報價系統」，網址 `https://showerli-glitch.github.io/yute-quotation/`）。動手前要先由使用者核准本文第 5 節的做法與第 6 節的決定（比照 OPS 拆檔的 Gate 1）。

## 1. 現況

- 單一檔案，2,096 行：CSS、HTML 與約 110 個函式全部在 `index.html`；沒有拆檔、沒有測試。
- 版面：左右兩欄。左欄 380px（可拖拉寬度）是「工項資料庫」（類別分頁、搜尋、點選加入；另有「編輯模式」改單價）。右欄是「報價單」（工項列可拖曳排序、數量與單價直接改、分段小計、管理費、稅、總計、備註、乾淨模式、設計模式、復原／重做）。
- 輸出：列印（`@media print` 版型，含表頭與明細頁）、匯出 Excel（從 cdnjs 載入 xlsx 0.18.5）、匯出／匯入 JSON。
- 儲存：
  - **工項資料庫存在各裝置的瀏覽器裡**（localStorage `yutesign_db`），並帶版本號 `DB_VERSION`；改過的單價只在那台電腦有效，換裝置就回到程式內建的 `DEFAULT_ITEMS`。
  - 編輯中的報價單存在 localStorage `yutesign_quote`。
  - 報價單可存到雲端硬碟共用資料夾（`SHARED_FOLDER_ID 17fGaw38tzYoQ3kPXnMN8bOhCSpjkjqwX`，授權範圍 `drive.file`），可列出、開啟、刪除。
  - Firebase 只用來通知「誰剛存了哪份報價」（路徑 `sync/lastSave`）。
- 登入：和 OPS 同一個 Google 用戶端（`239869421522-cqs68t3…`），同樣是「跳出小視窗」登入，限 `@yutesign.com`，登入狀態保留 4 小時（`SESSION_HOURS`）。
- 手機排版：**完全沒有**（沒有任何 `@media` 手機規則），在手機上就是縮小的電腦版。

## 2. 與 OPS 可以共用的

- Google 用戶端與 Firebase 專案相同；重新導向 URI `https://showerli-glitch.github.io/yute-quotation/` 已在 Google Cloud 設好（URI 1），所以「已安裝 app 改整頁轉址登入」的做法可以直接沿用。
- OPS 已完成的 PWA 零件：manifest／圖示／service worker 寫法、版本戳記與新版提示、iOS 26 已安裝 app 的畫面修正、單據上傳到雲端硬碟的模組、卡片版面的 CSS 手法、模擬測試工具（`scripts/smoke-lib.mjs`）。
- 深綠表頭、淺綠按鈕、底部分頁的視覺可以沿用，讓兩個系統看起來是同一套。

## 3. 手機上會遇到的問題

1. **跳出小視窗登入在已安裝的 iPhone app 會失敗**（OPS 已遇到，Google 回 400）；雲端硬碟授權也是小視窗。
2. **工項單價不同步**：手機上看到的是程式內建的預設單價，不是你在電腦上改過的價格。這是現有設計，手機版會讓問題更明顯。
3. 左右兩欄、拖曳排序、滑鼠右鍵式的操作在手機上不適用。
4. 列印與 Excel：iPhone 可以「列印 → 存成 PDF」和下載 Excel，但版面要實測。
5. **網址範圍重疊**：報價系統在 `/yute-quotation/`，OPS 在它底下的 `/yute-quotation/ops/`。報價系統如果裝 service worker 或 manifest 範圍設成根目錄，會蓋到 OPS；兩個 app 的範圍必須分開。

## 4. 手機版要做的畫面（建議）

- 底部分頁：「報價單」「工項」「雲端檔案」「更多」。
- 報價單：每個工項一張卡（名稱、數量 × 單價 = 小計，點開修改），上下移動取代拖曳，分段可收合；最下方固定顯示未稅、稅、總計。
- 工項：類別分頁＋搜尋，點一下加入報價單；編輯單價放在「更多」，只給有權限的人。
- 雲端檔案：列出、開啟、另存；儲存到同一個共用資料夾。
- 輸出：PDF（列印版型）與 Excel 照舊，從「更多」進入。
- 平板：沿用 OPS 的規則，直放用手機版、橫放用電腦版加大按鈕。

## 5. 建議做法與順序（比照 OPS）

1. **先拆檔**：把 `index.html` 依「工項資料庫／報價單計算／輸出（列印、Excel、JSON）／雲端硬碟／登入」搬到 `quotation/js/*` 和 `quotation/styles/*`，逐字搬移、不改行為，並建立驗證腳本與模擬測試。拆完先給你核准、上線一次。
2. 加 PWA 安裝（範圍限定在報價系統，不包含 `/ops/`）、版本戳記、已安裝 app 的整頁轉址登入。
3. 手機版畫面（第 4 節）。
4. 視第 6 節的決定，處理工項單價同步。

## 6. 需要你決定的事

1. **工項單價要不要跨裝置同步？** 不同步的話，手機報價會用到舊單價。要同步的話，有兩種存法：
   - (a) 存在 Firebase，像 OPS 一樣即時同步；
   - (b) 存成雲端硬碟上的一個檔案，開啟時讀取。
   我建議 (a)。這是新增資料，要你核准。
2. **兩個 app 分開還是合成一個？** 我建議分開：主畫面兩個圖示，各自的範圍，互不影響。
3. **誰可以改工項單價**：目前任何登入的人都能改（存在自己的電腦）。同步後，要不要限定只有你（或指定的人）能改？
4. **報價系統的登入時間**要不要也改成 8 小時，和 OPS 一致？

## 7. 使用者決定（2026-10-07）

1. 工項單價改存 Firebase，跨裝置同步；**所有登入的人都可以改單價**。
2. 報價系統和 OPS 分成兩個 app。
3. 報價系統登入時間也改成 8 小時。
4. 順序照第 5 節：先拆檔 → PWA 安裝與登入 → 手機畫面 → 單價同步。
